# Deployment and configuration

`npm run build` creates `dist/worker.js` and `dist/wrangler.json`, with
`APP_VERSION` set to the exact checkout commit. Public browser assets are in
`public/`. The Worker injects the Layer key server-side.

For Cloudflare, configure your own account/domain and namespace in
`wrangler.json`. The included route is the project's synthetic public demo;
replace it for your own deployment. Store `LAYER_API_KEY` as a Worker secret.
For private use also set `OWNER_TOKEN` as a secret, `APP_MODE=private`, and
three explicit distinct namespaces. Initialize the private namespace once.

```sh
npm ci
npm test
npm run build
npx wrangler deploy --config dist/wrangler.json
npx wrangler secret put LAYER_API_KEY --config dist/wrangler.json
# Private deployment only:
npx wrangler secret put OWNER_TOKEN --config dist/wrangler.json
```

Use a secret manager/piped input; never commit secrets or include them in command
arguments, logs or deployment receipts. The public demo mode denies writes and
call-adapter access even if private credentials accidentally exist in its env.
Do not deploy a private namespace under demo mode. The explicit namespace
contract prevents accidental reuse, but cannot infer whether a namespace holds
private data: deployers must assign the intended synthetic namespace.

| Variable | Purpose |
| --- | --- |
| `APP_MODE` | Required: `demo`, `private`, or `sandbox` |
| `LAYER_GATEWAY_URL` | Server-side Layer HTTPS gateway |
| `LAYER_API_KEY` | Server-side secret |
| `DEMO_NAMESPACE` | Explicit synthetic demo namespace |
| `PRIVATE_NAMESPACE` | Explicit owner's private namespace |
| `SANDBOX_NAMESPACE` | Separate synthetic sandbox namespace |
| `OWNER_TOKEN` | Required private/sandbox owner authentication secret |
| `SANDBOX_EXPIRES_AT` | Required valid future ISO datetime in sandbox mode |
| `APP_VERSION` | Exact deployed git commit, generated by build |
| `GRANOLA_ADAPTER_URL`, `GRANOLA_API_KEY` | Optional server-side adapter |
| `PORT` | Local server only (default 8787) |
| `STANDUP_URL`, `STANDUP_TOKEN` | CLI only, private API URL/auth |
| `UAT_COMMIT`, `UAT_DIR`, `UAT_NAMESPACE` | Exact acceptance candidate, evidence and fresh synthetic test namespace |

Keep a record of the prior Worker version/config before deploying. Validate the
new version with `/api/version`, health reads, ticket/paraphrase search and
`scripts/uat live URL`. If validation fails, restore the prior Worker version
and its configuration, then recheck the prior version endpoint. Never reset a
namespace during rollback. For a first deployment with no prior version, remove
only the new Worker/route on failure; retain evidence and fictional namespace.

Test namespaces are fresh, synthetic and owned by the test run. Integration and
preview cleanup delete only their own namespace after all consumers finish.
The local preview sandbox also has explicit one-hour expiry and auth. No public
interactive sandbox is deployed in this version.
